# 系统要求

EasySB 面向运行 Linux 的 VPS 或独立服务器。安装前请确认下面的系统、权限、域名与网络条件。

## 操作系统

| 项目 | 要求 |
| :--- | :--- |
| 发行版 | Debian 12（bookworm）、Debian 13（trixie）、Ubuntu 24.04（noble） |
| 更宽的上界 | 文档将支持范围表述为 Debian 12+ 与 Ubuntu 24.04+，前提是仍映射到上面这些受支持的发行版 |
| 初始化系统 | systemd |
| 权限 | root（安装脚本会在非 root 时尝试使用 `sudo`，但没有 `sudo` 会直接停止） |

apt 软件源覆盖 Debian 12/13 与 Ubuntu 24.04。安装脚本核对本机 `/etc/os-release` 是否受支持；不支持的发行版会被拒绝，而不是给出一个不存在的源。

::: warning
EasySB 只支持 systemd。OpenRC 等其它初始化系统不在当前支持范围内。
:::

## 架构

只发布两个架构，与 EasySB 覆盖的 BBR 内核一致：

| 架构 | Debian 拼写 |
| :--- | :--- |
| x86_64 | `amd64` |
| aarch64 | `arm64` |

其它架构没有对应的 `.deb`，安装脚本与软件源都不会提供。

## 域名与证书

除 VLESS + Vision + Reality 外，其余四个协议都基于标准 TLS，需要一个满足以下条件的域名：

- 域名已解析到本机地址（A 记录或 AAAA 记录）。
- 本机能用该域名申请到有效证书。
- 域名下没有会被 CDN 代理拦截的配置；若使用 Cloudflare 的小黄云，HTTP-01 校验会由 CDN 应答而无法到达本机。

VLESS + Vision + Reality 不依赖证书，可以只用它部署一台节点，无需域名。

::: tip
证书由面板进程内的 lego 通过 HTTP-01 standalone 方式向 Let's Encrypt 申请，不下载任何脚本。申请前会检查域名解析，并短暂停止内核以腾出 80 端口。域名下存在多条 A 记录时，Let's Encrypt 会校验每一条，残留的失效记录会导致签发失败。
:::

## 端口

| 端口 | 用途 |
| :--- | :--- |
| 80 | ACME HTTP-01 校验，必须在申请证书时可达且空闲 |
| 443 | 作为 TLS 协议可选的监听端口 |
| 8000 / 8001 / 8002 / 8003 / 8004 | 五个协议的默认端口，可在面板中修改 |
| 2080:3000 | Hysteria2 端口跳跃的默认 UDP 区间 |
| 8443 | 内置订阅服务的默认端口（`SUB_SERVE_PORT`） |

申请证书最慢的一步是真实引擎的校验，端口 80 被占用时面板会先报出占用者。申请期间会临时停止内核，因此 80 端口不能常驻在别的程序上。

## 网络访问

- 部署目标是能直接访问 GitHub 的海外主机。可选的 BBR 内核包从 `github.com` 的 release 直接下载，面板自身更新也读取 GitHub 上的公开版本信息。
- 面板不会为下载套用镜像前缀；为绕过本地网络问题而重新引入镜像并不符合预期用法。
- 工具箱中的解锁检测、测速与 IP 质量等条目会向被测服务发起请求，运行时需要相应的出网能力。打开工具箱不会自动运行任何条目。

## 资源

面板是单一静态二进制，常驻内存很小。真正的资源消耗来自节点本身与工具箱的跑分、磁盘 IO 等按需运行的测量，它们都由你手动触发。

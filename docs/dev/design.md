# 设计原则

这些是塑造代码库的决策。当某项改动与其中一条冲突时，把它当作一次设计讨论，而不是局部修改。

::: tip
本页描述的是意图与取舍，具体落地位置见 [架构](/dev/architecture)，命名与提交规则见 [约定](/dev/conventions)。
:::

## 单一静态二进制

sing-box 内核、证书签发与面板一起编译进单一静态二进制。热路径上没有运行时的包管理器调用，签发证书也不需要脚本解释器。`.deb` 安装后的快捷指令为 `sb`。

## 兼容旧版的状态

`/etc/sing-box/easysb.conf` 保留旧 bash 工具的 KV 布局。Go 构建与 shell 构建可以检查同一个部署。不要改动既有键；新增键即可。例外是只描述某个已不存在组件的键：v4 在删除 nginx 站点的同一次改动中移除了 `SUB_PORT` 与 `SUB_PATH`，因为没人读取的键是死重量。移除一个键需要移除它的组件，并更新所有提及它的文档。

## 模板可读优先

`templates/` 存放人类可阅读、可复制的 JSONC。sing-box 的解析器接受注释，EasySB 在渲染订阅时会剥离注释再输出标准 JSON。随二进制发布的订阅模板是 `internal/subscribe/tun-fakeip.json` 与 `internal/subscribe/mihomo.yaml`；可读镜像分别是 `templates/config/tun-fakeip.json` 与 `templates/config/mihomo.yaml`。

## 双语是构造出来的

每个面向用户的字符串都流经 `internal/i18n`。语言是一个 `Lang` 值（`C` 或 `E`），从不是全局布尔量。`L` 在运行时切换。新字符串必须在同一次提交中为两种语言补齐。

## 版本是数据而非代码

`VERSION` 是唯一事实来源，并通过 `go:embed` 编译进二进制。一次裸 `go build` 与一次正式发布因此报告同一个数字，没有需要保持同步的 `-ldflags -X main.version`，也没有第二个会漂移的常量。工作流以 `v<VERSION>` 标签发布；`internal/update` 从已发布的 `VERSION` 文件读取同一个数字，据此推导标签，并让 apt 完成升级。绝不要在多于一处硬编码发布标签。

## 非交互入口

任何开机单元需要的能力都必须能在没有 TTY 的情况下到达。`--apply-firewall` 是典范：它载入状态、应用规则、写入单元并退出。TUI 调用的是同一批包函数。

## 深色、安静的终端界面

默认配色是深色，以青色为主强调色。启动时 TUI 向终端询问背景色，并在背景为浅色时切换到加深的浅色配色，这样深色配色的近白正文永远不会落在白底上；`--theme`（或 `EASYSB_THEME`）强制 `dark` 或 `light`。界面使用备用屏幕、一种边框，每个状态（ok / warn / error）一种强调色。间距是显式的：分隔线与菜单项各得恰好一个空行，仪表盘在溢出矮终端之前先丢掉低优先级面板。

## 一屏两框

每个页面形状相同：第一行是状态条，然后是页面自己的看板在顶框、条目在底框。主菜单与栏目只在两个框里装什么上不同——字标与面板看板，对比某个栏目的看板——所以在页面之间移动时边框尺寸不变，按键提示也不移动。栏目用 `Esc` 退出，与子菜单一致，`--render --screen <id>` 可以绘制其中任意一个以检查版式。

## 长操作报告自己到哪了

一个会下载东西的任务把读数流式送到屏幕，而不是每兆字节打印一行：`internal/download` 通过 `Progress` 回调报告字节数，`internal/tui` 在任务报告器里收集它们并在日志上方画进度条。任何可能要花几分钟的事情——面板自身二进制、内核包——都走这条路径；只改动本地状态的步骤保持安静，而不是显示一个永不移动的进度条。内核已不在此列：它被编译进来，所以节点没有任何下载。

## 直接下载，宽容解析

部署目标是可直连 GitHub 的海外主机，所以二进制与内核包下载直连 `github.com`，不加镜像前缀。发布 tag 解析仍然容忍缺少 `v` 前缀，因为 `releases.atom` feed 会省略它。
